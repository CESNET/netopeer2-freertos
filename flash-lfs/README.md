# flash-lfs

This repository builds and manages the **LittleFS (LFS) filesystem image** that is flashed
onto the external flash of the target.

The LFS image contains the device's persistent configuration data: network configuration and
TLS certificates used by NETCONF-over-TLS.

## Repository layout

```
flash-lfs/
├── init_sysrepo.sh          # (Re-)generates input/etc/sysrepo from sysrepo/ sources
├── create_lfs_image.sh      # Packs the input/ folder into a littlefs binary image (lfs.bin)
├── mount_lfs_image.sh       # Extracts/mounts the contents of an existing lfs.bin for inspection
├── sysrepo/                 # Source YANG modules + startup datastore JSON (input for init_sysrepo.sh)
│   ├── yang/                 # YANG module definitions (IETF, ...)
│   └── startup/              # Startup configuration data (NACM, NETCONF server)
├── keys_tls/                # TLS certificates for a NETCONF client (ca/client/server .pem)
└── input/                   # Final tree that is packed into the LFS image (see below)
```

### `input/` — content of the resulting filesystem image

This folder mirrors exactly what ends up on the device's flash filesystem. It is partially
generated (`etc/sysrepo`) and partially maintained by hand (plain config files):

| Path | Purpose |
|---|---|
| `input/etc/sysrepo/` | sysrepo repository (YANG schemas + `data/` datastores), generated by `init_sysrepo.sh` |

## Prerequisites

### littlefs tools

`create_lfs_image.sh` and `mount_lfs_image.sh` require the `littlefs_create` /
`littlefs_extract` command-line tools, provided by the
[`littlefs_tools`](https://github.com/vppillai/littlefs_tools) Python package. Install it
via [pipx](https://pypa.github.io/pipx/) (recommended, keeps it isolated from the system
Python and puts the tools on `PATH`):

```bash
sudo apt install -y pipx   # if not already installed
pipx install littlefs_tools
```

This installs `littlefs_create`, `littlefs_extract`, `littlefs_list` and the unified
`littlefs` CLI to `~/.local/bin`. Alternatively, run `pip install littlefs_tools` inside a
virtual environment.

### libyang / sysrepo

`init_sysrepo.sh` requires [`libyang`](https://github.com/CESNET/libyang) and
[`sysrepo`](https://github.com/sysrepo/sysrepo) to be built and installed, providing the
`sysrepoctl` and `sysrepocfg` CLI tools used to install YANG modules and import the startup
datastore. It also requires `jq`. On Debian/Ubuntu:

```bash
sudo apt install -y jq
```

`libyang` and `sysrepo` are not packaged in Ubuntu's default repositories and typically need
to be built from source (in this order, since sysrepo depends on libyang):

```bash
# libyang
git clone https://github.com/CESNET/libyang.git
cd libyang && mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release .. && make -j"$(nproc)" && sudo make install
cd ../..

# sysrepo
git clone https://github.com/sysrepo/sysrepo.git
cd sysrepo && mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release .. && make -j"$(nproc)" && sudo make install
sudo ldconfig
```

Verify with `sysrepoctl -l` and `sysrepocfg -V` once installed.

## Scripts

### `init_sysrepo.sh`
Builds a fresh `input/etc/sysrepo` repository from scratch:
1. Checks that `sysrepoctl`, `sysrepocfg` and `jq` are installed.
2. Removes any previously generated `input/etc/sysrepo`.
3. Installs all YANG modules listed in the script (from `sysrepo/yang/`) via `sysrepoctl`,
   with the required features enabled per module.
4. Merges the startup datastore JSON files from `sysrepo/startup/` (NACM, NETCONF server)
   and imports them into the `startup` datastore via `sysrepocfg`.

Run this whenever the YANG models or startup configuration under `sysrepo/` change, before
building a new image.

```bash
./init_sysrepo.sh
```

The transport used for the NETCONF server (`ssh` or `tls`) is selected via the `TRANSPORT`
variable at the top of the script.

### `create_lfs_image.sh`
Packs the entire `input/` folder into a LittleFS binary image using `littlefs_create`.

```bash
./create_lfs_image.sh <output_folder>
```

Produces `<output_folder>/lfs.bin` (default block size 4096 B × 1024 blocks = 4 MB).
Requires `littlefs_create` to be available on `PATH`.

### `mount_lfs_image.sh`
The inverse operation: extracts the contents of an existing `lfs.bin` image into an
`output/` folder for inspection, using `littlefs_extract`.

```bash
./mount_lfs_image.sh <input_lfs_bin>
```

### `download_lfs_jlink.sh`
Flashes a previously built `lfs.bin` onto the target's external flash via SEGGER J-Link
(SWD), at the LFS partition address.

```bash
./download_lfs_jlink.sh <lfs_bin> [flash_address] [jlink_device] [speed_khz]
```

Defaults: device `MIMXRT1189xxxx_M33`, interface `SWD`, `4000` kHz, flash address
`0x28200000`. Requires `JLinkExe` (SEGGER J-Link software) on `PATH`.

## Typical workflow

```bash
# 1. Regenerate the sysrepo configuration from sysrepo/ sources
./init_sysrepo.sh

# 2. Adjust plain-value files under input/IVendorNameplate, input/NetworkConfiguration, input/gptp as needed

# 3. Pack everything in input/ into a littlefs image
./create_lfs_image.sh build

# 4. Flash the image onto the target
./download_lfs_jlink.sh build/lfs.bin
```

To inspect an existing image (e.g. one read back from a device):

```bash
./mount_lfs_image.sh build/lfs.bin
# contents are extracted to ./output
```

## Workflow: adding a new YANG module

1. **Add the `.yang` file(s)** to `sysrepo/yang/` (e.g. a new IETF/IEEE module).
2. **Register the module in `init_sysrepo.sh`**: add an entry to the `YANG_MODULES` array,
   in the correct dependency order (a module must come after any module it imports), including
   any required features, e.g.:
   ```bash
   "ietf-example-module@2024-01-01.yang -e feature-a -e feature-b"
   ```
   If the module has no features to enable, just list the filename.
3. **(Optional) add startup configuration**: if the new module needs default configuration
   data, add/extend a JSON file under `sysrepo/startup/` and reference it in the
   `SR_STARTUP_CONFIG_FILES` array (order matters — files are merged and applied in the
   listed order).
4. **Regenerate the sysrepo repository**:
   ```bash
   ./init_sysrepo.sh
   ```
   This reinstalls all modules (including the new one) via `sysrepoctl` and reimports the
   merged startup configuration via `sysrepocfg` into `input/etc/sysrepo`. Check the script
   output for install/import errors (e.g. missing dependencies or invalid features).
5. **Rebuild the LFS image** so the updated `input/etc/sysrepo` is included:
   ```bash
   ./create_lfs_image.sh build
   ```
6. **Flash the updated image** onto the target:
   ```bash
   ./download_lfs_jlink.sh build/lfs.bin
   ```

> Tip: after step 4, you can inspect `input/etc/sysrepo/data` directly, or use
> `sysrepocfg -X` / `sysrepoctl -l` (with `SYSREPO_REPOSITORY_PATH` pointed at
> `input/etc/sysrepo`) to verify the new module and its data were installed correctly before
> repacking the image.

## `keys_tls/`

Contains TLS certificates (`ca.pem`, `client.pem`, `server.pem`) used to test/connect to the
device's NETCONF-over-TLS server.
